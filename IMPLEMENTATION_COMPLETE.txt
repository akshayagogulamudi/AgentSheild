================================================================================
NOTIFICATION FLOW
================================================================================

1. Security gateway evaluates tool call
   → Decision: BLOCK or REQUIRE_APPROVAL

2. SecurityEvent recorded to database

3. BackgroundTask spawned (async, non-blocking)

4. NotificationService checks:
   - Is severity high enough? (yes → continue)
   - Was this incident notified recently? (no → continue)

5. NotificationRecord created with unique incident ID

6. Email + SMS sent (or simulated in mock mode):
   - Recipient sanitized → secrets redacted
   - EmailDelivery and SMSDelivery records created
   - Status set to: simulated (mock) or sent (live)

7. Frontend polls /api/notifications every 30s

8. Notifications dashboard displays live status

================================================================================
TROUBLESHOOTING
================================================================================

Notifications not appearing?
  1. Check NOTIFICATION_MODE (should be "mock" for testing)
  2. Verify severity of threat >= NOTIFICATION_MIN_SEVERITY
  3. Check logs for "[MAIL]" or error messages

Unicode errors on Windows?
  1. Add: $env:PYTHONIOENCODING="utf-8" before running Python

Database errors?
  1. Delete: agentshield.db
  2. Restart backend to recreate tables

SMTP/Twilio not working?
  1. Verify credentials in .env file
  2. Make sure NOTIFICATION_MODE=live
  3. Check logs for specific provider error messages
